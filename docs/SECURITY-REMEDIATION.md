# رفع آسیب‌پذیری‌های امنیتی رکاد

این مخزن نسخهٔ سخت‌شدهٔ [Behrad-Mahdavi/Rokad-Platform](https://github.com/Behrad-Mahdavi/Rokad-Platform) است. اصلاحات زیر از بررسی کد همان ریپو و الزامات `security.md` (موج اول: هویت، رازها، محدودیت نرخ، هدرها، کمترین دسترسی و جلوگیری از نشت داده) استخراج شده‌اند. در این سند مقدار هیچ رمز، توکن مانیتورینگ یا دادهٔ کاربری تکرار نشده است.

## کارهایی که قبل از استقرار باید انجام شود

1. همهٔ رازهایی که قبلاً داخل مخزن عمومی بوده‌اند را **بچرخانید**: JWT، رمز دیتابیس، Redis، MinIO، کلید رمزنگاری فیلد، pepper ایندکس کور، رمز سوپرادمین، و آدرس heartbeat مانیتورینگ.
2. در production این متغیرها را با مقدار تازه و طولانی تنظیم کنید: `JWT_ACCESS_SECRET`، `JWT_REFRESH_SECRET`، `APP_ENCRYPTION_KEY`، `APP_BLIND_INDEX_KEY`، `AUDIT_HASH_PEPPER`، `CORS_ORIGINS`.
3. اگر دیتابیس قبلاً با حساب‌های نمونهٔ seed ساخته شده، آن رمزها را عوض کنید. `prisma/seed.ts` دیگر در production اجرا نمی‌شود و رمز نمونهٔ سوپرادمین را قبول نمی‌کند.
4. `CORS_ORIGINS` باید فهرست دقیق مبدأ فرانت‌اند باشد، نه `*`.
5. توکن درگاه پیامک که در اسکریپت‌های تست ریشهٔ مخزن بالادستی هاردکد شده بود از این نسخه حذف شده است. آن توکن را در پنل سرویس‌دهنده باطل کنید و فقط از `AMOOT_API_KEY` استفاده کنید.

## اصلاحات اعمال‌شده

### هویت و نشست

- fallback رمز JWT که در کد عمومی بود حذف شد. در production اگر راز خالی، کوتاه یا از مقادیر منتشرشده باشد، سرویس بالا نمی‌آید.
- اگر دیتابیس هنگام لاگین یا اعتبارسنجی JWT در دسترس نباشد، دیگر توکن آزمایشی — از جمله با نقش مدیر پلتفرم — صادر نمی‌شود.
- توکن موقت احراز هویت دومرحله‌ای را نمی‌توان به‌جای توکن دسترسی استفاده کرد.
- توکن دسترسی دیگر از query string پذیرفته نمی‌شود. دانلود اکسل و چاپ فیش با بلیت ۶۰ثانیه‌ای انجام می‌شود.
- توکن‌ها در `localStorage` ماندگار نمی‌شوند. refresh فقط در `sessionStorage` می‌ماند و کوکی `HttpOnly` برای درخواست‌های same-site فایل تنظیم می‌شود.
- ثبت‌نام مدرسه جدید هم مشمول محدودیت تلاش ناموفق است. IP نامشخص دیگر از قفل brute-force معاف نیست.
- بازیابی رمز گاوصندوق دیگر رمزهای پیش‌فرض منتشرشده یا رمزهای خیلی ضعیف عمومی را حدس نمی‌زند و به Step-up 2FA نیاز دارد.

### جداسازی مدرسه

- درخواست بدون تننت دیگر به‌اشتباه «پلتفرم» حساب نمی‌شود و فیلتر چندمستأجری را دور نمی‌زند.
- کاربر مدرسه نمی‌تواند با هدر `x-tenant-id` وارد دادهٔ مدرسهٔ دیگر شود.
- مشاهده و ابطال نشست کاربر دیگر، برندینگ و اشتراک SaaS به تننت خود کاربر محدود شد، مگر برای مدیر پلتفرم.
- مقدار تننت در تراکنش RLS دیگر داخل رشتهٔ SQL چسبانده نمی‌شود.

### داده و فایل

- فایل‌های ماژول‌های حساس (پیام، تکلیف، آواتار، محتوا و مشابه) بدون امضای کوتاه‌مدت یا نشست معتبر قابل دریافت نیستند. پاسخ‌های API لینک امضاشده می‌سازند تا نمایش تصویر در فرانت‌اند نشکند.
- آپلود SVG و فایل‌های اجرایی/اسکریپتی رد می‌شود.
- مسیر فایل قبل از خواندن و حذف داخل ریشهٔ ذخیره‌سازی محصور می‌شود.
- CORS بازتابی با `credentials` روی فایل عمومی حذف شد.
- هدر `Referrer-Policy: no-referrer` روی پاسخ فایل گذاشته شد تا لینک فایل از طریق Referer نشت نکند.

### کمترین دسترسی

- نقش `STAFF` دیگر از همهٔ permissionها عبور نمی‌کند و باید از RBAC رد شود.
- عملیات مالی، حقوق و مدیریت نقش بدون 2FA فعال مسدود می‌شود.
- عضویت کانال گفتگو قبل از join شدن سوکت بررسی می‌شود. اتصال وب‌سوکت به کاربر فعال دیتابیس بسته است، نه فقط به ادعای داخل توکن.

### سطح و پیکربندی

- `.env.example` دیگر به‌عنوان تنظیمات اجرایی بارگذاری نمی‌شود و راز واقعی داخل آن نیست.
- Swagger در production پیش‌فرض خاموش است.
- سقف بدنهٔ JSON از ۱۵۰ مگابایت به ۶ مگابایت (قابل تنظیم) کاهش یافت.
- هدرهای امنیتی Helmet در production، از جمله CSP وقتی Swagger خاموش است، فعال است.
- پورت‌های Postgres و Redis و MinIO در Compose فقط روی localhost منتشر می‌شوند و رمز پیش‌فرض ندارند.
- endpoint عمومی heartbeat دیگر بدون توکن داخلی قابل فراخوانی نیست و آدرس مانیتورینگ از کد حذف شده است.
- جزئیات خطای زیرساخت در health check پروداکشن به کلاینت برنمی‌گردد.
- `security.txt` روی `/.well-known/security.txt` سرو می‌شود.

## دسترس‌پذیری، وابستگی و ورود قابل‌محاسبه

این بخش موارد مشاهده‌شده در گزارش ۹ اکتبر ۲۰۲۶ را می‌بندد. مقدار هیچ حساب، شناسه یا رمز واقعی در این سند نیست.

- سقف بدنهٔ JSON و فرم به‌صورت پیش‌فرض ۲ مگابایت است و تنظیم محیطی بالاتر از ۸ مگابایت نادیده گرفته می‌شود. بدنهٔ خیلی عمیق، خیلی پهن یا دارای کلیدهای خطرناک رد می‌شود.
- برای هر IP محدودیت نرخ جداگانه روی ورود، مسیرهای سنگین و سایر API وجود دارد. درخواست‌های معمولی بعد از ۳۰ ثانیه و مسیرهای ورود/خروجی بعد از ۱۲۰ ثانیه قطع می‌شوند.
- CSP دیگر خاموش نمی‌شود. در production اسکریپت فقط از همان مبدأ مجاز است. Swagger فقط وقتی روشن باشد استثنای محدود می‌گیرد و در production پیش‌فرض خاموش است.
- آپلود عمومی از ۱۵۰ مگابایت به ۳۲ مگابایت کاهش یافت. فایل اکسل ورودی قبل از parse حداکثر ۲ مگابایت، ۳ شیت و ۲۰۰۰ سطر است و فرمول اجرا نمی‌شود.
- وابستگی `xlsx` نسخهٔ ۰.۱۸.۵ حذف شد. خواندن و نوشتن از بستهٔ وصله‌شدهٔ ۰.۲۰.۳ انجام می‌شود، چون نسخهٔ رسمی npm وصله ندارد.
- حداقل نسخهٔ NestJS به ۱۰.۴.۲۲ رسید تا باگ `FileTypeValidator` نسخهٔ ۱۰.۴.۱۵ در بازهٔ نصب نباشد.
- `.npmrc` دیگر اجازهٔ اجرای همهٔ build scriptها و اسکریپت‌های pre/post را نمی‌دهد. فقط بسته‌های فهرست `pnpm.onlyBuiltDependencies` می‌توانند اسکریپت نصب اجرا کنند.
- image مربوط به MinIO روی یک release ثابت است، نه `latest`. Redis سقف حافظه دارد. پورت‌های Compose فقط روی localhost هستند و کانتینرها `no-new-privileges` دارند.
- رمز اعضای جدید تصادفی است و `mustChangePassword` برایشان روشن می‌شود. ورود با این پرچم فقط اجازهٔ تغییر رمز می‌دهد و refresh نشست کامل نمی‌سازد. مهاجرت پایگاه‌داده همین پرچم را برای ردیف‌های موجود روشن و نشست‌های باز را باطل می‌کند.
- بازیابی رمز از روی کد ملی، موبایل یا نام کاربری حذف شد. اگر نسخهٔ رمزنگاری‌شده در گاوصندوق نباشد، باید رمز جدید تنظیم شود. تنظیم کلید و backfill گاوصندوق هم Step-up می‌خواهند.
- `GET /users` به نقش‌های عضو همان مرکز محدود است و نام کاربری، موبایل و کد ملی برنمی‌گرداند.
- وب‌سوکت سقف اتصال برای IP و کاربر، سقف اندازهٔ پیام، سقف اتاق و سقف رویداد در دقیقه دارد.

قبل از استقرار واقعی، مهاجرت `prisma/migrations/20261013120000_force_password_change` را اعمال کنید و همهٔ رازهای قبلاً منتشرشده را بچرخانید. رمزهای قدیمی که از شناسه ساخته شده بودند باید در اولین ورود عوض شوند.

## بررسی

```bash
npm run security:check
```

این دستور تست سیاست امنیتی و اسکن باقی‌ماندن رازهای منتشرشده را اجرا می‌کند.
